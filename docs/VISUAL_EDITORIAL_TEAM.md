# Visual editorial team

Status: proposed operating plan. This names responsibilities and deliverables;
it does not start agents, install a second orchestrator, or enable recurring jobs.
Use the existing content-operations brand cells and VIS asset graph.

## The team's useful job

Turn owned ideas, product proof and image collections into a coherent website
and release sequence. Every prominent image should help a particular audience
understand, feel or do something. Keep each brand recognizable, preserve useful
existing surfaces and make every selection explainable and reversible.

The existing content cell already has Researcher, Strategist, Creator, Editor/QA,
Publisher and Analyst roles. Extend that structure with visual responsibilities;
keep its maker/verifier separation, content calendar and approval gates. Its
documented model defaults and provider connections require current admission and
capability checks before execution. A role specification is not proof of a running
team, connected channel or working automation.

These are responsibilities, not seven new always-on processes. Routine work can
run serially through one capable lead and small role-specific packets. Invoke a
separate reviewer at the consequential review boundary when admitted. Additional
agents require a specific independent artifact, exclusive output paths, budget,
stop condition and the current dispatch authority. No fanout occurred for this plan.

## One decision packet per piece of work

The creative lead gives each task:

- Brand, audience, user situation and intended route/action.
- One message and the emotion that supports it, with the actual product/source proof.
- Exact page/section/component or social-series role.
- Current component and assets to preserve; source and target revisions.
- Candidate asset/version IDs, known rights and provenance, and unknowns.
- Composition/crop requirements, text-safe areas, mobile treatment and alt-text role.
- Available time/model budget, reviewer and approval owner.
- Acceptance evidence and a recovery/rollback path.

A packet can request an image, a real screenshot, an authored diagram, an editorial
crop, or no new image. The output type follows the communication job. Generated
media must not impersonate a real customer result, product screen, person or location.

## Intelligent processing without constant re-analysis

1. Resolve source identity and exact content hash before any model work. Preserve
   all locations and references when duplicates converge.
2. Read source context, explicit brand/project links and existing placement records.
   Build a shortlist against the open slot briefs in the existing task queue.
3. Extract useful searchable attributes: subject, scene, material, light, palette,
   focal position, visual density, available crop, emotional energy and text space.
   Record which were measured, visually judged or inferred, with confidence.
4. Inspect shortlisted actual images. Evaluate brand fit, message/proof fit,
   composition, mobile crop, character consistency and visible defects separately.
5. Return a small comparison board and a recommendation with reasons. Keep the
   current image and a no-image treatment available when they serve the slot.
6. Save selected/rejected-for-this-slot decisions, crop coordinates, reviewer,
   human feedback, inspected version and reference/rubric revision in VIS records
   or the reconciled existing intake contract. Do not start a parallel catalog.
7. Reuse unchanged analysis. Re-evaluate when bytes, model/task, rubric, reference
   set or intended use changes. Preserve actual human taste separately from predictions.
8. Prepare only requested derivatives and channel exports. Record actual source use
   and publication evidence after integration and verification.

The attribute extractor, semantic matcher and versioned cache above remain proposed.
The current VIS audit establishes coverage, not that this intelligence pipeline runs.

## How taste becomes useful memory

Use a small reference set per brand and use-case: a few positive examples, a few
rejected examples with reasons, and current public work that should be preserved.
Have Frank compare real alternatives within a placement context. Capture the reason
and scope: "too busy behind the homepage headline" differs from "wrong character"
and from "not the direction for this brand". A slot rejection does not ban an image.

Keep brand identity, campaign mood and technical suitability separate. One release
can be warmer or more dramatic without changing the whole brand. Record a real
change in preference as dated human feedback with its source; repeated agent policy
text is not new founder feedback. Use the existing feedback outbox/taste ledger and
memory synchronization path with receipts.

Do not use an averaged aesthetic score to overrule rights, canon, truthful product
claims, explicit human rejection or missing approval. Explain trade-offs. Keep
uncertainty visible when a reviewer has not inspected the actual crop in context.

## Frontend feel contract

Selected/read guidance: design-capability-routing and Emil design engineering.
Applied here to planning: preserve each site's visual identity, use a static-first
composition, name the job of motion and keep repeated navigation/filtering immediate.

Before implementation, bind the brand's current component/feel contract: press
feedback, named transition properties/easing/duration, interruption behavior and
elements that stay still. The brand and accessibility rules take precedence.
No new gestures are proposed here; gesture specialist pass is skipped. No universal
button skin, image-card style, animation library or palette is introduced.

Implementation acceptance includes real inspection at 375, 768 and 1440 widths,
keyboard/focus, touch targets, reduced motion, rapid reversal, image loading/failure
and layout stability. An image must not be the only accessible explanation of a
product mechanism. An optional audio/video piece has a complete silent/static path.
No UI was built or visually verified in this planning slice. Impeccable finish is
deferred until an actual surface has been inspected.

## Work cadence and acceptance

First complete one brand and one connected release: an existing website placement,
one explanatory detail and a small social sequence from the same real source.
Use the matching section in `BRAND_PLACEMENT_STRATEGY.md`. The sample slot file is
a planning interchange example, not a running queue or an approved publishing plan.

Use the existing brand calendar for a proposed weekly review: brief new work,
select/edit candidates, obtain review, publish after approval, then read results.
Do not install this cadence as a job without the existing schedule authority.

Measure something the intended user can do: understand a product, inspect a source,
choose a relevant route, export a useful artifact, or engage with a complete story.
Record denominators, date window and missing data for website/social metrics.
Clicks alone do not establish value, and sparse results do not establish a winning
aesthetic. Compare the same task with ordinary manual curation/Cloudinary browsing
before claiming time or cost savings from an intelligent team.

The first useful outcome is a reviewed, placed artifact with traceable context and
one channel adaptation that survives mobile inspection. A roster or planning file
alone does not complete the creative or engineering outcome.
